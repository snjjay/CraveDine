Exactly. Think of migrations as a sequence of database changes.

You normally don't manually edit the migration files. You change your Entity/DbContext, then let EF Core generate the 
migration.

The basic process

Step 1 — Change your C# model
==========================================================
For example, currently:

public class Area
{
    public int Id { get; set; }
    public string Name { get; set; }
}

You decide you need:

public string Description { get; set; }


Step 2 — Create a migration
==========================================================

In Visual Studio → Package Manager Console:

Add-Migration AddAreaDescription

EF Core looks at your current model and creates a migration describing the change.


Step 3 — Apply the migration
==========================================================
Update-Database

Now SQL Server gets the new column.

Area.cs
   ↓
Add-Migration
   ↓
Migration created
   ↓
Update-Database
   ↓
SQL Server changed

// ==========================================================
// MIGRATION EXAMPLES
// ==========================================================
//
// 🟢 ADD A FIELD
//
// Add property to Entity:
//
// public string Description { get; set; }
//
// Then:
//
// Add-Migration AddAreaDescription
// Update-Database
//
// → Adds Description column to the database.
//
// ----------------------------------------------------------
//
// 🔴 REMOVE A FIELD
//
// Remove property from Entity:
//
// public string Description { get; set; }
//
// Then:
//
// Add-Migration RemoveAreaDescription
// Update-Database
//
// → Removes the column.
// ⚠️ Existing data in that column can be lost.
//
// ----------------------------------------------------------
//
// 🔵 ADD A TABLE
//
// Create new Entity:
//
// public class Coupon { ... }
//
// Add to DbContext:
//
// DbSet<Coupon> Coupons
//
// Then:
//
// Add-Migration AddCoupons
// Update-Database
//
// → Creates Coupons table.
//
// ----------------------------------------------------------
//
// 🗑️ DELETE A TABLE
//
// Remove Entity + DbSet:
//
// Add-Migration RemoveCoupons
// Update-Database
//
// → Removes the table.
// ⚠️ Existing table data can be lost.
//
// ----------------------------------------------------------
//
// ✏️ RENAME A FIELD
//
// Rename property:
//
// Name → AreaName
//
// Then:
//
// Add-Migration RenameAreaName
//
// ⚠️ CHECK the generated migration first.
// Make sure EF renames the column rather than
// deleting the old column and creating a new one.
//
// Then:
//
// Update-Database
//
// ----------------------------------------------------------
//
// 🔗 CHANGE A RELATIONSHIP
//
// Change Entity / DbContext relationship.
//
// Then:
//
// Add-Migration ChangeRestaurantRelationship
// Update-Database
//
// → Updates foreign keys/relationships.
//
// ==========================================================
//
// 🔑 BASIC PATTERN:
//
// Change Entity / DbContext
//        ↓
// Add-Migration Name
//        ↓
// CHECK migration
//        ↓
// Update-Database
//
// ==========================================================
